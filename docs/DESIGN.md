## D-3 الگوهای بصری مشترک

### کارت شیشه‌ای `.glass-card`
- پس‌زمینه نیمه‌شفاف سفید
- border روشن + highlight داخلی
- گوشهٔ `--radius-xl`
- استفاده در پنل‌ها، متریک‌ها، فیلترها، صندوق

### دکمه
| کلاس | ظاهر |
|------|------|
| `.btn-primary` | گرادیان primary-strong → primary، متن سفید |
| `.btn-secondary` | outline / سطح شیشه‌ای |
| `.btn-ghost` | بدون پر، برای اکشن فرعی |
| `.btn-sm` | ارتفاع کمتر (~36px) |

### فیلد
- `.input` / `.select` / `.textarea`
- focus: حلقه `primary-soft`
- حداقل ارتفاع لمسی ~44px جایی که ادمین/فرم است

### Toggle
- به‌جای checkbox در شاخص‌ها و فیلتر «فقط گزارش‌های من»
- جهت LTR داخل سوئیچ؛ برچسب فارسی کنارش

### Skeleton
- `.SectionSkeleton` هنگام لود هر بخش گزارش

## P صفحات و رفتار UI

### P-1 ورود `/login`
- کارت مرکزی شیشه‌ای
- فیلد کاربر / رمز
- بدون سایدبار کامل (صفحهٔ مستقل)

### P-2 خانه `/`
- کارت‌های نوع بررسی (سریع، اول، تمدید، …)
- ادامهٔ آخرین گزارش اگر وجود داشته باشد
- شمارش بخش‌ها روی هر نوع

### P-3 تنظیم بررسی `/setup/:typeId`
- انتخاب برند/شعبه (جستجو)
- بازهٔ شمسی
- بخش‌های گزارش (اجباری / پیشنهادی / اختیاری)
- نکات پیگیری دسته‌بندی‌شده

### P-4 گزارش `/report/:typeId/:branchId`
مراحل افقی (journey chips):

| مرحله | کلید | توضیح UI |
|--------|------|----------|
| خلاصه | `summary` | جمع وضعیت‌ها + اسکور |
| بخش‌ها | `section` | یک بخش در هر قدم؛ skeleton تا لود |
| نکات پیگیری | `diag` | لیست چک‌لیست UpdateDiag |
| ارسال | `send` | PDF + قالب مشتری + فرم دستیار |

- وضعیت tone روی متریک‌ها رنگی است
- کلیک وضعیت می‌تواند فیلتر کند
- لاگ سرور با هر عوض شدن مرحله → صندوق گزارش

### P-5 صندوق گزارش‌ها `/reports`  ★ منوی «گزارش‌ها»
**هدف:** اینباکس تیم — چه گزارشی ساخته شده و در چه مرحله‌ای است.

| بلوک UI | محتوا |
|---------|--------|
| آمار بالا | کل / در حال انجام / ارسال‌شده |
| فیلترها | کاربر · مرحله · نوع بررسی · Toggle فقط من |
| جدول | کاربر، نوع/مجموعه، بج مرحله، پیشرفت (n از m)، آخرین فعالیت، باز کردن |

بج مرحله:
- summary · section · diag · send · sent (رنگ‌های جدا در CSS)

**مالکیت و لاگ (الزامی):**
- کلید گزارش = `typeId:branchId` (تیمی؛ با باز شدن توسط دیگری عوض نمی‌شود)
- ستون کاربر = **سازنده**؛ اگر کس دیگری ویرایش کرده «آخرین ویرایش: …» نشان داده می‌شود
- هر پیشرفت/ارسال در `activity[]` لاگ می‌شود — rule/skill: `monitoring-report-audit`

### P-6 تنظیمات ادمین `/admin`
تب‌ها:
1. بخش‌های گزارش — per review-type
2. نکات پیگیری — دسته‌ای + select-all
3. **کیفی شاخص‌ها** — گرید ۲ ستونهٔ باکس فیچر؛ کارت متریک داخل هر باکس
4. قالب پیام — گرید تگ `Name@` مثل کلاب + textarea

قوانین دسترسی UI:
- ویرایش شاخص فقط **سوپرادمین**
- افزودن/حذف شاخص از UI فعلاً نیست (از کد/دستیار)

### P-7 کاربران `/users`
- CRUD کاربر
- نقش: user / admin / (ساخت admin فقط توسط superadmin)

### P-8 راهنما `/help`
- FAQ و گام‌های ساخت گزارش

### P-9 تاریخچه محلی `/history`
- هنوز هست (localStorage مرورگر) ولی از منوی اصلی حذف شده
- لینک مستقیم برای دیباگ باقی است
